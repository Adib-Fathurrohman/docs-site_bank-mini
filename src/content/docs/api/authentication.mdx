## Login satu pintu

<Endpoint method="POST" path="/api/login" limit="5/menit per username/identifier + IP (staf) atau 30/menit per IP (id_token nasabah)" />

Pintu masuk gateway untuk semua peran. Kirim kredensial staf (`username` + `password`)
atau ID token Firebase nasabah (`id_token`). Nilai `data.actor` memberi tahu portal yang aktif.

| Field | Aturan |
| --- | --- |
| `username`, `password` | Staf: wajib bersamaan. `username` maks. 255 |
| `id_token` | Nasabah: string ID token dari Firebase Authentication (Google atau email/password) |

Jika `username` diisi, autentikasi staf dijalankan. Jika `id_token` diisi, autentikasi nasabah
Firebase dijalankan. Jika keduanya tidak diisi, server mengembalikan `422`.

```http
POST /api/login
Accept: application/json
Content-Type: application/json

{ "username": "teller", "password": "password" }
```

```json title="200 (staf) — contoh dari basis data demo"
{
  "data": {
    "actor": "staff",
    "token": "<token>",
    "token_type": "Bearer",
    "user": {
      "id": 3, "username": "teller", "full_name": "Teller Loket 1",
      "class": "XI AK 1", "phone": "081200000001", "role": "teller", "is_active": true,
      "created_at": "2026-10-27T13:10:33.000000Z", "updated_at": "2026-10-27T13:10:33.000000Z"
    }
  }
}
```

```json title="200 (nasabah) — contoh dari basis data demo"
{
  "data": {
    "actor": "customer",
    "token": "12|5pJ...",
    "token_type": "Bearer",
    "expires_at": "2026-12-02T02:00:00.000000Z",
    "customer": {
      "id": 1,
      "account_number": "RPL-2026-001",
      "nis": "20260001",
      "full_name": "Budi Santoso",
      "email": "budi.santoso@example.test",
      "activation_status": "activated",
      "activated_at": "2026-11-02T01:00:00.000000Z",
      "pin_set": true,
      "class": "X",
      "group": "1",
      "major": { "id": 1, "code": "RPL", "major_name": "Rekayasa Perangkat Lunak" },
      "account_status": "active",
      "balance": 500000,
      "created_at": "2026-10-27T13:10:33.000000Z",
      "updated_at": "2026-11-02T01:00:00.000000Z",
      "deleted_at": null
    }
  }
}
```

Jika tidak ada kredensial yang diberikan:

```json title="422 Unprocessable Entity"
{
  "message": "Isi username dan password (staf), atau masuk dengan akun Google/email (nasabah).",
  "errors": {
    "username": ["Isi username dan password (staf), atau masuk dengan akun Google/email (nasabah)."]
  }
}
```

## Portal login khusus

<Endpoint method="POST" path="/api/staff/login" limit="5/menit per username + IP" />

Hanya menerima body kredensial staf: `{ "username": "...", "password": "..." }`.

<Endpoint method="POST" path="/api/customer/auth/login" limit="30/menit per IP" />

Pintu masuk login nasabah menggunakan ID token Firebase:

```json
{ "id_token": "<firebase-id-token>" }
```

Respons `200` sama dengan format login nasabah di atas. Jika akun belum diaktivasi pertama kali atau token ditolak, API mengembalikan kode kesalahan terstruktur:

| Status | `code` | Keterangan |
| --- | --- | --- |
| 401 | `firebase_token_invalid` | Tanda tangan tidak valid, kedaluwarsa, dicabut, atau akun Firebase dinonaktifkan |
| 403 | `account_not_linked` | Akun Firebase belum terhubung ke nasabah mana pun. Aplikasi mengarahkan pengguna ke layar aktivasi NIS |
| 403 | `provider_not_allowed` | Provider selain `password` atau `google.com` |
| 403 | `email_not_verified` | Email pada akun Firebase belum diverifikasi |
| 403 | `account_inactive` | Rekening bank mini telah ditutup |
| 503 | `auth_unavailable` | Layanan Firebase tidak dapat dihubungi atau belum dikonfigurasi |

## Aktivasi rekening nasabah

<Endpoint method="POST" path="/api/customer/activation" limit="20/menit per IP" />

Endpoint publik untuk menautkan akun Firebase pertama kali ke rekening nasabah berdasarkan nomor NIS:

```json
{
  "nis": "20260001",
  "id_token": "<firebase-id-token>"
}
```

Email yang terverifikasi pada token Firebase harus persis sama dengan email yang didaftarkan admin pada rekening nasabah tersebut.

**200 OK:** Mengembalikan format data login nasabah (`activation_status: "activated"`, `pin_set: false`). Aplikasi kemudian meminta nasabah membuat PIN awal via `POST /api/customer/pin/setup`.

Kode penolakan:

| Status | `code` | Keterangan |
| --- | --- | --- |
| 403 | `activation_mismatch` | NIS tidak ditemukan atau email Firebase tidak cocok dengan data pendaftaran admin (satu pesan umum untuk pencegahan enumerasi) |
| 403 | `email_not_verified` | Email belum diverifikasi di Firebase |
| 403 | `account_inactive` | Rekening nasabah berstatus nonaktif/tutup |
| 409 | `already_activated` | Rekening nasabah ini sudah terhubung ke akun Firebase lain |
| 409 | `identity_already_linked` | Akun Firebase ini sudah terhubung ke rekening nasabah lain |

## Staf

<Endpoint method="GET" path="/api/staff/me" roles="admin,supervisor,teller" />

Staf yang sedang masuk: `{ "data": Staff }`. Panggil saat aplikasi web dibuka untuk memvalidasi token yang tersimpan.

<Endpoint method="POST" path="/api/staff/logout" roles="admin,supervisor,teller" />

Mencabut token yang sedang dipakai: `200 { "message": "Berhasil keluar." }`.

## Nasabah

<Endpoint method="GET" path="/api/customer/me" roles="customer" />

Nasabah yang sedang masuk: `{ "data": Customer }` beserta data jurusan.

<Endpoint method="POST" path="/api/customer/logout" roles="customer" />

Mencabut token sesi yang sedang dipakai di perangkat ini: `200 { "message": "Berhasil keluar." }`.

<Endpoint method="POST" path="/api/customer/logout-all" roles="customer" />

Mencabut **seluruh** token Sanctum milik nasabah di semua perangkat: `200 { "message": "Berhasil keluar dari semua perangkat." }`.

<Aside type="note" title="Masa berlaku sesi">
Token staf berlaku **480 menit** (8 jam) sesuai `SANCTUM_EXPIRATION`. Token nasabah berlaku lebih panjang
(**43.200 menit** / 30 hari) sesuai `CUSTOMER_SESSION_MINUTES`, dan tanggal kedaluwarsanya disertakan pada field `expires_at` saat login.
</Aside>
