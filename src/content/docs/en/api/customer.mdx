Every endpoint is scoped to the account of the **customer** token; `?customer_id=` and
similar parameters are ignored. Login, profile and logout are under
[Authentication](/en/api/authentication/); withdrawal approval is under
[Withdrawal authorizations](/en/api/withdrawal-authorizations/#customer-side).

<Aside type="note" title="Customers cannot move money">
No customer endpoint creates a transaction or a withdrawal request. Customers can only
approve or reject a withdrawal that a teller started.
</Aside>

## Balance

<Endpoint method="GET" path="/api/customer/balance" roles="customer" />

```json title="200 — example from the demo database"
{
  "data": {
    "account_number": "RPL-2026-001", "full_name": "Budi Santoso", "account_status": "active",
    "balance": 595000, "min_balance": 10000, "as_of": "2026-10-27T13:10:40.302817Z"
  }
}
```

## Statement

<Endpoint method="GET" path="/api/customer/transactions" roles="customer" />

The statement, newest first, default `per_page` 20. Filters `from`, `to`, `type`.
[StatementLine](#statementline-object) rows leave out tellers and journals:

```json title="200 — example from the demo database"
{
  "data": [
    { "id": 5, "type": "withdrawal", "direction": "out", "description": "Tarik tunai", "amount": 30000, "balance_after": 595000, "created_at": "2026-10-27T13:10:37.000000Z" },
    { "id": 4, "type": "deposit", "direction": "in", "description": "Setor tunai", "amount": 125000, "balance_after": 625000, "created_at": "2026-10-27T13:10:36.000000Z" }
  ]
}
```

<Endpoint method="GET" path="/api/customer/transactions/{transaction}" roles="customer" />

One own line (**404** for another customer's).

<Endpoint method="GET" path="/api/customer/statement/export" roles="customer" />

Own statement PDF (`mutasi-RPL-2026-001.pdf`) with `?from=&to=`: opening balance, every
line with a running balance, and totals.

## Digital card

<Endpoint method="GET" path="/api/customer/card" roles="customer" />

The same shape as the admin card, with `qr_payload` (`BANKMINI:{account_number}`) to
show as a QR code at the counter. The QR payload only identifies the customer; it
authorizes nothing (L17).

## Change PIN

<Endpoint method="POST" path="/api/customer/pin" roles="customer" />

| Field | Rules |
| --- | --- |
| `current_pin` | Required, 6 digits |
| `new_pin` | Required, 6 digits, different from `current_pin`, confirmed |
| `new_pin_confirmation` | Must equal `new_pin` |

**200** `{ "message": "PIN berhasil diubah." }`. A wrong `current_pin` counts toward the
same lock as login and withdrawals (**422** with `remaining_attempts`).

## StatementLine object

`id`, `type`, `direction` (`in`/`out`), `description` (Indonesian label), `amount`,
`balance_after`, `created_at`.
