## Single login gateway

<Endpoint method="POST" path="/api/login" limit="5 per minute per username/identifier + IP (staff) or 30 per minute per IP (customer id_token)" />

The single entry point for all roles. Send either staff credentials (`username` + `password`)
or a customer Firebase ID token (`id_token`). The `data.actor` field indicates which portal to open.

| Field | Rule |
| --- | --- |
| `username`, `password` | Staff: required together. `username` max 255 |
| `id_token` | Customer: Firebase Authentication ID token string (Google or email/password) |

If `username` is present, staff authentication runs. If `id_token` is present, customer Firebase
authentication runs. If neither is provided, the server returns `422`.

```http
POST /api/login
Accept: application/json
Content-Type: application/json

{ "username": "teller", "password": "password" }
```

```json title="200 (staff) — demo database example"
{
  "data": {
    "actor": "staff",
    "token": "<token>",
    "token_type": "Bearer",
    "user": {
      "id": 3, "username": "teller", "full_name": "Teller Loket 1",
      "class": "XI AK 1", "phone": "081200000001", "role": "teller", "is_active": true,
      "created_at": "2026-10-27T13:10:33.000000Z", "updated_at": "2026-10-27T13:10:33.000000Z"
    }
  }
}
```

```json title="200 (customer) — demo database example"

    "actor": "customer",

{
  "message": "Isi username dan password (staf), atau masuk dengan akun Google/email (nasabah).",
  "errors": {
    "username": ["Isi username dan password (staf), atau masuk dengan akun Google/email (nasabah)."]
  }
}
```

## Portal-specific logins

<Endpoint method="POST" path="/api/staff/login" limit="5 per minute per username + IP" />

Accepts only staff credentials: `{ "username": "...", "password": "..." }`.

<Endpoint method="POST" path="/api/customer/auth/login" limit="30 per minute per IP" />

Dedicated customer sign-in endpoint using a Firebase ID token:

```json
{ "id_token": "<firebase-id-token>" }
```

A `200` response matches the customer login format above. If the account has not been activated or the token is refused, structured error codes are returned:

| Status | `code` | Cause |
| --- | --- | --- |
| 401 | `firebase_token_invalid` | Bad signature, expired, revoked, or disabled Firebase account |
| 403 | `account_not_linked` | Firebase user is not bound to any Bank Mini customer yet (prompt user to activate with NIS) |
| 403 | `provider_not_allowed` | Sign-in provider other than `password` or `google.com` |
| 403 | `email_not_verified` | Email address on the Firebase token is not verified |
| 403 | `account_inactive` | Bank Mini account has been closed |
| 503 | `auth_unavailable` | Firebase service is unreachable or unconfigured |

## Customer account activation

<Endpoint method="POST" path="/api/customer/activation" limit="20 per minute per IP" />

Public endpoint to bind a Firebase identity to a customer account for the first time, verified by NIS:

```json
{
  "nis": "20260001",
  "id_token": "<firebase-id-token>"
}
```

The verified email on the Firebase token must match the email registered by the administrator.

**200 OK:** Returns the standard customer login payload (`activation_status: "activated"`, `pin_set: false`). The client then prompts the customer to create their PIN via `POST /api/customer/pin/setup`.

Refusal error codes:

| Status | `code` | Cause |
| --- | --- | --- |
| 403 | `activation_mismatch` | NIS not found or email does not match registered record (anti-enumeration message) |
| 403 | `email_not_verified` | Email is not verified in Firebase |
| 403 | `account_inactive` | Bank account is closed |
| 409 | `already_activated` | Customer account is already bound to a different Firebase user |
| 409 | `identity_already_linked` | This Firebase user is already bound to another customer account |

## Staff

<Endpoint method="GET" path="/api/staff/me" roles="admin,supervisor,teller" />

Current authenticated staff member: `{ "data": Staff }`. Call on app startup to validate stored tokens.

<Endpoint method="POST" path="/api/staff/logout" roles="admin,supervisor,teller" />

Revokes the active bearer token: `200 { "message": "Berhasil keluar." }`.

## Customer

<Endpoint method="GET" path="/api/customer/me" roles="customer" />

Current authenticated customer: `{ "data": Customer }` with major relation.

<Endpoint method="POST" path="/api/customer/logout" roles="customer" />

Revokes the active bearer token on this device: `200 { "message": "Berhasil keluar." }`.

<Endpoint method="POST" path="/api/customer/logout-all" roles="customer" />

Revokes **all** Sanctum tokens across all devices for this customer: `200 { "message": "Berhasil keluar dari semua perangkat." }`.

<Aside type="note" title="Session lifetimes">
Staff tokens are valid for **480 minutes** (8 hours) per `SANCTUM_EXPIRATION`. Customer sessions last **43,200 minutes** (30 days)
per `CUSTOMER_SESSION_MINUTES`, and include the explicit expiration timestamp in `expires_at` upon login.
</Aside>
