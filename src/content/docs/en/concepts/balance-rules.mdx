## Money is always integer Rupiah

Every amount in requests and responses is **integer Rupiah** with no decimals:
`50000` means Rp50.000. Send numbers, not formatted strings.

| Rule | Value | Enforced by |
| --- | --- | --- |
| Transaction amount | Integer 1 – 100,000,000 | Form request |
| Stored amount | Always > 0 | `CHECK amount > 0` |
| Customer balance | Never negative | `CHECK balance >= 0` |
| Amount in words | `amount_in_words` computed by the server, e.g. `seratus dua puluh lima ribu rupiah` | Resource |

## Minimum balance

A withdrawal is refused if it would leave less than the **minimum balance**. The admin
sets it with the `min_balance` setting (default `10000`, from `BANK_MIN_BALANCE`).

```text
allowed when:  balance − amount ≥ min_balance
```

Example refusal (`422`) with a balance of Rp1.000.000 and a minimum of Rp10.000:

```json
{ "message": "Saldo tidak mencukupi. Saldo minimum Rp10.000 harus tetap tersisa; penarikan maksimal Rp990.000." }
```

| Situation | Minimum balance applies? |
| --- | --- |
| Cash withdrawal (PIN at the counter) | Yes, when the transaction is recorded |
| Withdrawal request approved in the app | Yes, when the request is created **and** when it is completed |
| Cash deposit | Not relevant |
| Deposit correction | No. May go below the minimum, but never below zero |

Customers can see the minimum balance in `GET /api/customer/balance` (`min_balance`).

## Account status

| Status | Login | Deposit / withdraw | Correction | Teller lookup | Set by |
| --- | :-: | :-: | :-: | :-: | --- |
| `active` | ✓ | ✓ | ✓ | ✓ | On creation; admin edit |
| `suspended` | ✓ | — | ✓ | ✓ | Admin edit |
| `inactive` | — | — | — | — | Only by closing (graduation), which also soft-deletes the account |

- Suspended accounts can still log in and view their balance. Their tokens are not
  revoked.
- Closing an account (`POST /admin/customers/{id}/deactivate`) sets the status to
  `inactive`, revokes all the customer's tokens and soft-deletes the account.
  Transactions and journal lines are untouched.
- Restoring a closed account is **not available**.

## Account numbers

Format: `{MAJOR CODE}-{SCHOOL YEAR}-{SERIAL}`, e.g. `RPL-2026-001`.

| Part | Rule |
| --- | --- |
| Major code | From `majors.code`: AK, BR, BD, MP, DKV, RPL, TKJ, LPS (seeded) |
| School year | The year in which the July–June school year started when the account was opened. October 2026 → `2026`; June 2027 → `2026`; July 2027 → `2027` |
| Serial | At least 3 digits, zero-padded, restarting per major and school year, never reused (closed accounts count). After `999` comes `1000` |

Numbers are generated by `CustomerService::create`, which retries up to 3 times if two
accounts are opened at the same moment and collide. The account number and balance
**cannot be changed** through the API; changing the major does not change the number.

## Limitations to know

<Aside type="caution" title="L1 · Clients must use multiples of Rp100">
The backend does not require multiples of 100, but cash can only be counted in
denominations of Rp100 or more. An amount like Rp150 makes the shift **impossible to
close** until that transaction is corrected (verified). Clients should enforce
multiples of Rp100.
</Aside>

| # | Limitation | Impact |
| --- | --- | --- |
| L5 | Closing an account does not require a zero balance and cannot be undone. With a minimum balance > 0, the last Rp10.000 can never be withdrawn | Warn before closing an account that still has money |
| L15 | `customers.balance` is a 32-bit integer (max Rp2.147.483.647) | Not a concern at school scale |

The full list is in [Known limitations](/en/reference/known-limitations/).
