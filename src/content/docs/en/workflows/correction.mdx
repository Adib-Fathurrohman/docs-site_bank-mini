A saved transaction is never edited. A typo is reversed with a **correction
transaction**, then the teller records the right amount as a new transaction.

## Summary

| | |
| --- | --- |
| Actor | Teller, authorized by a supervisor |
| Endpoint | `POST /api/teller/transactions/{id}/correct` |
| Preconditions | The original is the teller's own `deposit`/`withdrawal`; not corrected yet; its shift is still active (`open` or `rejected`) and is the teller's active shift |
| Input | `reason` (max 255), `supervisor_username`, `supervisor_password` |
| Limits | 10 requests per minute per teller; supports `Idempotency-Key` |

<Steps>

1. The teller picks a transaction from the running shift and enters a reason.
2. The supervisor types their own username and password.
3. The backend creates a new transaction of the same amount in the opposite direction
   (`deposit_correction` or `withdrawal_correction`), with `note` = the reason and
   `authorized_by` = the supervisor.
4. The teller records the right amount as a new deposit or withdrawal.

</Steps>

## Rules

| Rule | Result when broken |
| --- | --- |
| Only the teller's own transaction | `404` |
| A transaction can be corrected only once | `422 Transaksi ini sudah pernah dikoreksi.` |
| Corrections cannot be corrected | `422 Transaksi koreksi tidak dapat dikoreksi lagi.` |
| Only in the shift where the original was recorded, while that shift is active | `422 Koreksi hanya dapat dilakukan pada shift tempat transaksi asli dicatat, …` |
| Correct credentials of an active supervisor | `422` with `errors.supervisor_password` = `Otorisasi supervisor gagal. …` |
| A deposit correction cannot make the balance negative | `422 Saldo nasabah sudah tidak mencukupi untuk membatalkan setoran ini.` |
| Account `active` or `suspended` | Allowed on suspended accounts |
| At most 10 per minute | `429` |

A deposit correction may take the balance **below the minimum balance**, but never
below zero. Shift totals are net of corrections, so the drawer still reconciles at
closing.

<Aside type="note" title="Corrections after a rejected report">
If the supervisor rejects the daily report, the shift becomes active again and its
transactions can be corrected again, on any day, until the shift is closed again.
</Aside>

## Not available

- Partial corrections (a correction always reverses the full amount).
- Editing or deleting transactions.
- Correction approval in the customer app.

Full endpoints: [Teller API](/en/api/teller/#corrections).
