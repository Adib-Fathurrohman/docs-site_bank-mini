## Overview

| | |
| --- | --- |
| Actors | All staff and customers |
| Entry endpoints | `POST /api/login`, `/api/staff/login`, `/api/customer/auth/login`, `/api/customer/activation` |
| Mechanism | Laravel Sanctum personal access bearer tokens, stored hashed in `personal_access_tokens` |
| Customer auth | Firebase Authentication (Google OAuth or Email/Password) client SDK, verified by server adapter |
| Session lifetimes | **Staff:** 480 minutes (8 hours) absolute. **Customer:** 43,200 minutes (30 days) via `CUSTOMER_SESSION_MINUTES` |
| Cookies / sessions | None (stateless API) |

<Steps>

1. Client sends **one** credential set:

   ```json title="Staff"
   { "username": "teller", "password": "password" }
   ```

   ```json title="Customer (Firebase ID Token)"
   { "id_token": "<firebase-id-token>" }
   ```

2. For staff, the backend checks bcrypt passwords and ensures `is_active = true`. For customers, the server verifies token signatures, audience, account status, and maps the `firebase_uid` to the customer record.

3. On success, the backend creates a Sanctum token:

   ```json title="200 (staff)"
   {
     "data": {
       "actor": "staff",
       "token": "3|FsAYFafTXVEvVS53…",
       "token_type": "Bearer",
       "user": { "id": 3, "username": "teller", "full_name": "Teller Loket 1", "role": "teller", "is_active": true }
     }
   }
   ```

   ```json title="200 (customer)"
   {
     "data": {
       "actor": "customer",
       "token": "12|5pJ…",
       "token_type": "Bearer",
       "expires_at": "2026-12-02T02:00:00.000000Z",
       "customer": {
         "id": 1,
         "account_number": "RPL-2026-001",
         "nis": "20260001",
         "full_name": "Budi Santoso",
         "email": "budi.santoso@example.test",
         "activation_status": "activated",
         "pin_set": true,
         "account_status": "active",
         "balance": 500000
       }
     }
   }
   ```

4. The client routes the user according to `data.actor` and role.

## First-time customer activation flow

Students do not manage a local password for Bank Mini. The admin creates the account with the student's email, and the student activates the app themselves:

## App session unlock

Because customer sessions last up to 30 days (`CUSTOMER_SESSION_MINUTES`), the mobile app locks its UI when backgrounded or closed.

- Reopening the app prompts for the 6-digit PIN and verifies it via `POST /api/customer/unlock` `{pin}`.
- Three consecutive failures lock the PIN for 15 minutes (`pin_locked_until`).
- App unlock is a client-side gate to protect an unattended phone; the Sanctum token remains valid for API calls.

## Using tokens and logging out

Pass the token on every request:

```http
GET /api/customer/me
Accept: application/json
Authorization: Bearer <token>
```

| Actor | Profile | Logout (this device) | Logout (all devices) |
| --- | --- | --- | --- |
| Staff | `GET /api/staff/me` | `POST /api/staff/logout` | — |
| Customer | `GET /api/customer/me` | `POST /api/customer/logout` | `POST /api/customer/logout-all` |

- `POST /api/customer/logout` revokes only the active token on the current device.
- `POST /api/customer/logout-all` revokes **all** Sanctum tokens for that customer across all devices.

## Refusal codes

| Status | Code / Message | Meaning | Client action |
| --- | --- | --- | --- |
| `401` | `Unauthenticated.` | Token missing, invalid, or expired | Delete stored token, show login |
| `401` | `firebase_token_invalid` | Firebase session expired or invalid | Re-authenticate with Firebase |
| `403` | `account_not_linked` | Firebase user not yet bound to an account | Direct to NIS activation screen |
| `403` | `activation_mismatch` | NIS does not match registered email | Display activation error message |
| `403` | `Fitur ini khusus untuk staf bank.` | Customer token on staff endpoint | Clear token, show login |
| `403` | `Fitur ini khusus untuk nasabah.` | Staff token on customer endpoint | Clear token, show login |
| `403` | `Akun staf ini sudah dinonaktifkan.` | Staff blocked | Clear token, show login |
| `403` | `Rekening ini sudah tidak aktif.` | Customer account closed | Clear token, show login |
| `422` | `pin_not_set` | Customer has not set up a PIN | Direct to PIN setup screen |

Full reference: [Authentication API](/en/api/authentication/).
