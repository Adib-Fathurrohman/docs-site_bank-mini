The schema is created by the migrations in `database/migrations`. This page covers the
business tables only; Laravel's own tables (`cache`, `jobs`, `sessions`,
`password_reset_tokens`) and `personal_access_tokens` (Sanctum tokens) are not covered in
detail.

<Aside type="note" title="General principles">
- All money is stored as `integer` Rupiah.
- Every foreign key uses `ON DELETE RESTRICT`: anything with history cannot be deleted.
- `CHECK` constraints are added with `ALTER TABLE` so they apply on MariaDB.
</Aside>

## `cash_counts`

Cash counted per denomination when opening and closing a shift.

| Column | Type | Notes |

| `daily_report_id` | FK → `daily_reports` | RESTRICT |
| `stage` | enum (`opening`, `closing`) | From `CashCountStage` |

## `transactions`

| Column | Type | Notes |
| --- | --- | --- |
| `id` | bigint | PK, the transaction number on receipts |
| `user_id` | FK → `users` | Recording teller |
| `customer_id` | FK → `customers` | |
| `daily_report_id` | FK → `daily_reports` | Shift |
| `type` | enum `deposit`, `withdrawal`, `deposit_correction`, `withdrawal_correction` | `CHECK` on the type list |
| `amount` | integer unsigned | `CHECK (amount > 0)` |
| `balance_before`, `balance_after` | integer unsigned | |
| `corrects_transaction_id` | FK → `transactions`, nullable, **unique** | One correction per transaction |
| `authorized_by` | FK → `users`, nullable | Supervisor who authorized a correction |
| `note` | string, nullable | Correction reason |
| `idempotency_key` | string(100), nullable | **Unique with `user_id`** |

Indexes: (`customer_id`, `created_at`), (`user_id`, `created_at`).

```sql title="chk_transactions_correction"
(type IN ('deposit', 'withdrawal') AND corrects_transaction_id IS NULL AND authorized_by IS NULL)
OR (type IN ('deposit_correction', 'withdrawal_correction') AND corrects_transaction_id IS NOT NULL AND authorized_by IS NOT NULL)
```

## `withdrawal_authorizations`

Withdrawal requests approved by the customer in the app (Mode A).

| Column | Type | Notes |
| --- | --- | --- |
| `id` | bigint | Internal PK, never exposed |
| `public_id` | ULID, unique | The `{id}` in URLs and responses |
| `teller_id`, `customer_id`, `daily_report_id` | FK | RESTRICT |
| `amount` | integer unsigned | `CHECK (amount > 0)` |
| `status` | enum `pending`, `approved`, `rejected`, `cancelled`, `expired`, `consumed` | Default `pending` |
| `expires_at` | timestamp | Customer's decision deadline |
| `approved_at`, `approval_expires_at` | timestamp, nullable | Teller's completion deadline |
| `rejected_at`, `cancelled_at` | timestamp, nullable | |
| `cancel_reason` | string(20), nullable | `teller` or `shift_closed` |
| `consumed_at` | timestamp, nullable | |
| `transaction_id` | FK → `transactions`, nullable, **unique** | One transaction per request |

Indexes: (`customer_id`, `status`), (`teller_id`, `status`). **There is no PIN
column.**

```sql title="chk_wa_consumed and chk_wa_approved"
-- a consumed request always points at its withdrawal; no other status does
(status = 'consumed' AND transaction_id IS NOT NULL AND consumed_at IS NOT NULL)
OR (status <> 'consumed' AND transaction_id IS NULL)

-- approved and consumed requests always have the approval times
status NOT IN ('approved', 'consumed') OR (approved_at IS NOT NULL AND approval_expires_at IS NOT NULL)
```

## `personal_access_tokens`

Sanctum tokens: `tokenable` (morph to `users` or `customers`), `name` (`staff-portal` or
`customer-portal`), `token` (hash, unique), `abilities` (not used), `last_used_at`,
`expires_at`.

<Aside type="caution" title="Old databases must be rebuilt">
Earlier migrations were edited during development. A database created before those
edits must be rebuilt with `php artisan migrate:fresh --seed` (which deletes its data).
</Aside>
