## Production deployment URLs

Every service runs on the `rumput.tech` VPS, each with its own domain and HTTPS certificate:

- **Staff Web App:** [https://bank.rumput.tech/api/](https://bank.rumput.tech/api/) — counter teller operations, supervisor reviews, bank administration, and auditing. The app lives under the `/api/` path; `https://bank.rumput.tech` redirects there.
- **Backend REST API:** `https://api-bank.rumput.tech/api` — the base URL for both clients (`VITE_API_BASE_URL` in the staff web app, `EXPO_PUBLIC_API_URL` in the customer app). Health check: `https://api-bank.rumput.tech/up`.
- **Customer App:** an Android APK, distributed through GitHub Releases in `bank-mini-mobile`. There is no web version.
- **Documentation Site:** [https://docs-bank.rumput.tech](https://docs-bank.rumput.tech) — architecture guides, 83 endpoint API reference, database schema, and compliance notes.

<Aside type="note" title="Cross-domain authentication">
The staff web app and the API are on different domains, so the API allows the origin `https://bank.rumput.tech` through CORS (`CORS_ALLOWED_ORIGINS`). Both clients send Sanctum Bearer tokens in the `Authorization` header, not cookies, so `SANCTUM_STATEFUL_DOMAINS` and CSRF are not used. The Android app is not subject to CORS.
</Aside>
