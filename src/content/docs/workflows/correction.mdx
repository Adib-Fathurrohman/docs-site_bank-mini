Transaksi yang tersimpan tidak pernah diubah. Salah ketik dibatalkan dengan
**transaksi koreksi**, lalu teller mencatat nominal yang benar sebagai transaksi
baru.

## Ringkasan

| | |
| --- | --- |
| Aktor | Teller, diotorisasi supervisor |
| Endpoint | `POST /api/teller/transactions/{id}/correct` |
| Prasyarat | Transaksi asli adalah `deposit`/`withdrawal` milik teller sendiri; belum pernah dikoreksi; shift asalnya masih aktif (`open` atau `rejected`) dan merupakan shift aktif teller |
| Input | `reason` (maks. 255), `supervisor_username`, `supervisor_password` |
| Batas | 10 permintaan per menit per teller; mendukung `Idempotency-Key` |

<Steps>

1. Teller memilih transaksi dari shift yang sedang berjalan dan mengisi alasan.
2. Supervisor mengetik username dan password-nya sendiri.
3. Backend membuat transaksi baru dengan nominal sama dan arah berlawanan
   (`deposit_correction` atau `withdrawal_correction`), dengan `note` = alasan dan
   `authorized_by` = supervisor.
4. Teller mencatat nominal yang benar sebagai setoran atau penarikan baru.

</Steps>

## Aturan

| Aturan | Akibat jika dilanggar |
| --- | --- |
| Hanya transaksi milik teller sendiri | `404` |
| Satu transaksi hanya dapat dikoreksi sekali | `422 Transaksi ini sudah pernah dikoreksi.` |
| Transaksi koreksi tidak dapat dikoreksi | `422 Transaksi koreksi tidak dapat dikoreksi lagi.` |
| Hanya di shift tempat transaksi asli dicatat, selama shift itu aktif | `422 Koreksi hanya dapat dilakukan pada shift tempat transaksi asli dicatat, …` |
| Kredensial supervisor aktif yang benar | `422` dengan `errors.supervisor_password` = `Otorisasi supervisor gagal. …` |
| Koreksi setoran tidak boleh membuat saldo negatif | `422 Saldo nasabah sudah tidak mencukupi untuk membatalkan setoran ini.` |
| Rekening `active` atau `suspended` | Boleh pada rekening yang ditangguhkan |
| Maksimal 10 per menit | `429` |

Koreksi setoran boleh membuat saldo **di bawah saldo minimum**, tetapi tidak di bawah
nol. Total shift dihitung bersih dari koreksi, sehingga laci tetap cocok saat penutupan.

<Aside type="note" title="Koreksi setelah laporan ditolak">
Jika supervisor menolak laporan harian, shift kembali aktif dan transaksinya dapat
dikoreksi lagi, pada hari apa pun, sampai shift ditutup ulang.
</Aside>
