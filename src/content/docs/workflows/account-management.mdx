Semua alur di halaman ini hanya dapat dijalankan **administrator**. Supervisor dapat
membaca daftar rekening dan staf, tetapi tidak dapat mengubahnya.

### Membuka rekening

| | |
| --- | --- |
| Endpoint | `POST /api/admin/customers` |
| Prasyarat | Jurusan ada (`GET /api/majors`) |
| Input | `nis`, `full_name`, `email` (wajib, unik), `class` (`X`/`XI`/`XII`), `major_id`, `group` (`1`–`4`) |
| Aturan PIN | Admin **tidak menetapkan PIN**. Mengirim field `pin` ditolak `422`. PIN dibuat siswa setelah aktivasi |
| Proses | `CustomerService::create` membuat nomor `{KODE}-{TAHUN}-{URUT}` |
| Efek database | Baris `customers`: status `active`, status aktivasi `pending`, saldo `0`, `pin` null |
| Respons | `201` Customer (`activation_status: "pending"`, `pin_set: false`) |
| Gagal | `422` validasi (NIS atau email sudah dipakai, termasuk rekening yang ditutup); `403` bukan admin |

Saldo awal selalu `0`. Uang dapat langsung disetor di loket teller meskipun nasabah belum mengaktifkan aplikasi.

### Impor nasabah dari pembukuan lama

| | |
| --- | --- |
| Endpoint | `POST /api/admin/customers/import` |
| Input | `file` (wajib, `.xlsx`/`.csv`), `transactions_file` (opsional, atau sheet `Transaksi`) |
| Kapasitas | Maks. 1.000 nasabah dan 10.000 baris transaksi historis |
| Kolom nasabah | NIS, Nama, Email (opsional), Kelas, Jurusan, Rombel, Saldo (opsional), No Rekening (opsional) |
| Kolom transaksi | NIS, Tanggal, Jenis (`setor`/`tarik`), Nominal, Keterangan |
| Saldo awal | Sisa saldo yang tidak dijelaskan oleh riwayat transaksi otomatis dijadikan saldo awal (*"Saldo awal dari pembukuan lama"*) |
| Efek database | Baris `customers` dibuat massal; transaksi dikaitkan ke `customer_imports` (`daily_report_id: null`) |
| Transaksi atomik | Gagal total (*all-or-nothing*) jika ada format data salah, NIS duplikat, atau saldo negatif |


### Mengubah data dan menangguhkan rekening

| | |
| --- | --- |
| Endpoint | `PUT\|PATCH /api/admin/customers/{id}` |
| Input | Sebagian dari `nis`, `full_name`, `email`, `class`, `major_id`, `group`, `account_status` (`active`/`suspended` saja) |
| Aturan email | `email` hanya dapat diubah selama status aktivasi masih `pending`. Setelah diaktifkan, email terkunci (`422`) |
| Aturan PIN | Mengirim `pin` ditolak `422` (gunakan endpoint reset PIN khusus) |
| Tidak dapat diubah | Nomor rekening dan saldo. Mengganti jurusan tidak mengganti nomor |
| Gagal | `422` validasi; `404` rekening sudah ditutup |

Menangguhkan rekening tidak mencabut token nasabah, namun nasabah tidak dapat melakukan penarikan.

### Reset PIN nasabah

| | |
| --- | --- |
| Endpoint | `POST /api/admin/customers/{id}/pin-reset` |
| Kapan dipakai | Nasabah lupa PIN |
| Efek | Mengosongkan kolom `pin`, menyetel `pin_failed_attempts = 0`, dan mengosongkan `pin_locked_until` (blokir terbuka) |
| Langkah selanjutnya | Nasabah masuk ke aplikasi dengan akun Firebase terdaftar, lalu membuat PIN baru via `POST /api/customer/pin/setup` |
| Respons | `200` dengan data Customer terbaru (`pin_set: false`) |

### Menutup rekening (lulus)

| | |
| --- | --- |
| Endpoint | `POST /api/admin/customers/{id}/deactivate` |
| Proses | Satu transaksi database: status `inactive`, hapus semua token nasabah, nonaktifkan user di Firebase, soft delete |
| Validasi | Tidak ada pemeriksaan saldo |
| Efek | `deleted_at` terisi. Transaksi dan jurnal tidak berubah |
| Gagal | `404` jika sudah ditutup |

<Aside type="caution" title="Bayarkan saldo dulu">
Penutupan tidak mensyaratkan saldo nol dan tidak dapat dibatalkan. Sisa saldo harus
ditarik lewat teller **sebelum** rekening ditutup, dan aturan saldo minimum tetap
berlaku (keterbatasan L5).
</Aside>

Rekening yang ditutup tetap dapat dibaca lewat `GET /api/customers?trashed=with|only`,
`GET /api/customers/{id}`, PDF mutasi, dan log audit.

### Data kartu nasabah

`GET /api/admin/customers/{id}/card` mengembalikan data untuk mencetak kartu, termasuk
`qr_payload` (`BANKMINI:{account_number}`). Backend tidak membuat gambar QR; klien
yang merender payload menjadi QR.

## Manajemen staf

| Alur | Endpoint | Efek database | Kegagalan penting |
| --- | --- | --- | --- |
| Membuat teller/supervisor | `POST /api/admin/staff` | Baris `users` (password di-hash, `is_active` true) | `422` (peran `admin` ditolak, username sudah dipakai) |
| Mengubah staf | `PUT\|PATCH /api/admin/staff/{id}` | Update `users` (termasuk password, peran teller↔supervisor) | `403` untuk akun admin |
| Memblokir | `POST /api/admin/staff/{id}/block` | `is_active` false, semua token dihapus | `403` untuk akun admin |
| Membuka blokir | `POST /api/admin/staff/{id}/unblock` | `is_active` true | `403` untuk akun admin |
| Menghapus | `DELETE /api/admin/staff/{id}` | Baris dan token dihapus jika tidak dirujuk data lain | `409` jika ada transaksi, laporan, persetujuan, atau perubahan pengaturan yang merujuknya |
| Impor | `POST /api/admin/staff/import` (multipart `file`) | Semua baris dimasukkan dalam satu transaksi database; password yang kosong dibuat acak dan dikembalikan sekali | `422` dengan kunci `rows.{i}.{field}`; tidak ada yang dimasukkan |

<Aside type="note" title="Blokir, bukan hapus">
Staf yang pernah bertransaksi tidak dapat dihapus karena riwayatnya harus tetap
menunjuk ke akunnya (`ON DELETE RESTRICT`). Blokir akunnya.
</Aside>
