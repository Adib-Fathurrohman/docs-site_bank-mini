Skema dibuat oleh migration di `database/migrations`. Halaman ini hanya membahas tabel
bisnis; tabel bawaan Laravel (`cache`, `jobs`, `sessions`, `password_reset_tokens`)
dan `personal_access_tokens` (token Sanctum) tidak dibahas rinci.

<Aside type="note" title="Prinsip umum">
- Semua uang disimpan sebagai `integer` Rupiah.
- Semua foreign key memakai `ON DELETE RESTRICT`: data yang punya riwayat tidak dapat
  dihapus.
- Constraint `CHECK` dibuat dengan `ALTER TABLE` agar berlaku di MariaDB.
</Aside>

## `customers`

Rekening tabungan siswa.

| Kolom | Tipe | Catatan |
| --- | --- | --- |
| `id` | bigint | PK |
| `account_number` | string | Unik, dibuat otomatis |
| `nis` | string | Unik |
| `email` | string, nullable | **Unik**. Diisi admin saat pembuatan; untuk aktivasi aplikasi |
| `firebase_uid` | string(128), nullable | **Unik**. Disimpan saat aktivasi akun pertama kali via Firebase; tersembunyi |
| `email_verified_at` | timestamp, nullable | Waktu verifikasi email Firebase |
| `activated_at` | timestamp, nullable | Waktu aktivasi aplikasi mobile |
| `full_name` | string | |
| `class` | enum `X`, `XI`, `XII` | |
| `major_id` | FK → `majors` | RESTRICT |
| `group` | enum `1`–`4` | Kelas paralel |
| `account_status` | enum `active`, `suspended`, `inactive` | Bawaan `active` |
| `pin` | string, nullable | Hash bcrypt, tersembunyi. Dibuat sendiri oleh nasabah setelah aktivasi |
| `pin_failed_attempts` | tinyint unsigned, bawaan 0 | Penghitung PIN salah berturut-turut |
| `pin_locked_until` | timestamp, nullable | Akhir blokir PIN |
| `balance` | integer, bawaan 0 | `CHECK (balance >= 0)` |
| `deleted_at` | timestamp, nullable | Soft delete (rekening ditutup) |

```sql title="Constraint CHECK pada customers"
-- Rekening teraktivasi harus memiliki identitas Firebase
CHECK (activated_at IS NULL OR firebase_uid IS NOT NULL)

-- PIN hanya boleh ada setelah rekening diaktifkan oleh nasabah
CHECK (pin IS NULL OR activated_at IS NOT NULL)
```

## `transactions`

| Kolom | Tipe | Catatan |
| --- | --- | --- |
| `id` | bigint | PK, nomor transaksi di struk |
| `user_id` | FK → `users` | Teller pencatat (atau admin saat impor) |
| `customer_id` | FK → `customers` | |
| `daily_report_id` | FK → `daily_reports`, nullable | Shift teller; bernilai null untuk transaksi hasil impor |
| `customer_import_id` | FK → `customer_imports`, nullable | Batch impor pembukuan lama |
| `type` | enum `deposit`, `withdrawal`, `deposit_correction`, `withdrawal_correction` | `CHECK` daftar jenis |
| `amount` | integer unsigned | `CHECK (amount > 0)` |
| `balance_before`, `balance_after` | integer unsigned | |
| `corrects_transaction_id` | FK → `transactions`, nullable, **unik** | Satu koreksi per transaksi |
| `authorized_by` | FK → `users`, nullable | Supervisor yang mengotorisasi koreksi |
| `note` | string, nullable | Alasan koreksi atau catatan saldo awal |
| `idempotency_key` | string(100), nullable | **Unik bersama `user_id`** |

Indeks: (`customer_id`, `created_at`), (`user_id`, `created_at`).

```sql title="chk_transactions_correction dan chk_transactions_source"
-- koreksi membutuhkan transaksi yang dikoreksi dan supervisor
(type IN ('deposit', 'withdrawal') AND corrects_transaction_id IS NULL AND authorized_by IS NULL)
OR (type IN ('deposit_correction', 'withdrawal_correction') AND corrects_transaction_id IS NOT NULL AND authorized_by IS NOT NULL)

-- transaksi berasal dari shift teller atau impor pembukuan lama (hanya setor/tarik)
(daily_report_id IS NOT NULL AND customer_import_id IS NULL)
OR (daily_report_id IS NULL AND customer_import_id IS NOT NULL AND type IN ('deposit', 'withdrawal'))
```

## `withdrawal_authorizations`

Permintaan penarikan yang disetujui nasabah di aplikasi (Mode A).

| Kolom | Tipe | Catatan |
| --- | --- | --- |
| `id` | bigint | PK internal, tidak pernah diekspos |
| `public_id` | ULID, unik | `{id}` di URL dan respons |
| `teller_id`, `customer_id`, `daily_report_id` | FK | RESTRICT |
| `amount` | integer unsigned | `CHECK (amount > 0)` |
| `status` | enum `pending`, `approved`, `rejected`, `cancelled`, `expired`, `consumed` | Bawaan `pending` |
| `expires_at` | timestamp | Batas keputusan nasabah |
| `approved_at`, `approval_expires_at` | timestamp, nullable | Batas penyelesaian teller |
| `rejected_at`, `cancelled_at` | timestamp, nullable | |
| `cancel_reason` | string(20), nullable | `teller` atau `shift_closed` |
| `consumed_at` | timestamp, nullable | |
| `transaction_id` | FK → `transactions`, nullable, **unik** | Satu transaksi per permintaan |

Indeks: (`customer_id`, `status`), (`teller_id`, `status`). **Tidak ada kolom PIN.**

```sql title="chk_wa_consumed dan chk_wa_approved"
-- consumed selalu menunjuk ke penarikannya; status lain tidak pernah
(status = 'consumed' AND transaction_id IS NOT NULL AND consumed_at IS NOT NULL)
OR (status <> 'consumed' AND transaction_id IS NULL)

-- approved dan consumed selalu punya waktu persetujuan
status NOT IN ('approved', 'consumed') OR (approved_at IS NOT NULL AND approval_expires_at IS NOT NULL)
```

## `customer_push_tokens`

Token registrasi FCM perangkat nasabah untuk menerima push notification permintaan otorisasi penarikan.

| Kolom | Tipe | Catatan |
| --- | --- | --- |
| `id` | bigint | PK |
| `customer_id` | FK → `customers` | CASCADE on delete |
| `personal_access_token_id` | FK → `personal_access_tokens` | CASCADE on delete (dihapus saat sesi logout atau kedaluwarsa) |
| `token` | string(255) | Unik, FCM registration token perangkat |
| `platform` | string(10) | `android` atau `ios` |
| `created_at`, `updated_at` | timestamp | |

## `personal_access_tokens`

Token Sanctum: `tokenable` (morph ke `users` atau `customers`), `name` (`staff-portal`
atau `customer-portal`), `token` (hash, unik), `abilities` (tidak dipakai),
`last_used_at`, `expires_at`.

<Aside type="caution" title="Database lama harus dibangun ulang">
Migration lama diubah selama pengembangan. Database yang dibuat sebelum perubahan itu
harus dibangun ulang dengan `php artisan migrate:fresh --seed` (menghapus datanya).
</Aside>
